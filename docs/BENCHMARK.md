# Benchmark: jev-compactor vs vanilla compaction

Measured 2026-09-18 with `packages/bench` on the transcripts checked into this repo, so anyone can
re-run it. Jev model `jev-1.13.0` via `jev-latest`; the summarization arm uses Claude Sonnet 5
(`claude-sonnet-5`, priced at $2 / $10 per million input / output tokens). Raw results:
[`docs/benchmark/long-noisy.json`](benchmark/long-noisy.json),
[`docs/benchmark/short-fixtures.json`](benchmark/short-fixtures.json).

## The three arms

| Arm | What it does |
|---|---|
| **jev-compactor** | this package, default thresholds (`dropThreshold` 0.7, `keepRecent` 4), `trigger: 'always'`; run twice per transcript to record determinism |
| **truncate-oldest** | keep the first message, drop the oldest turns until the estimate fits the budget — what most loops do when the window fills (`baselines/truncate.mjs`) |
| **summarize** | one Claude call that rewrites the history as a continuation summary, told explicitly to "preserve exact file paths, commands, and error messages" (`baselines/anthropic.mjs`) |

## Metrics

- **saved** — 1 − tokens after / tokens before, with the same 2.5-chars-per-token estimate for every arm.
- **latency / cost** — wall-clock and dollars for the compaction call itself (Jev's reported usage;
  Claude's reported usage at list price; truncation is free).
- **path fidelity** — share of file paths, URLs and dotted identifiers in the output that exist in
  the original. Anything below 100% is a hallucinated reference the agent may act on.
- **evidence retention** — share of caller-named snippets that survive verbatim in the output. The
  snippets are facts the agent needs at the end of the session: for the long transcript, two ticket
  ids, the migration-freeze constraint and the original failure text, all stated **only in the first
  few turns**; for the short fixtures, the assertion message, the buggy constant and the function
  signature.

## Long, noisy transcript — the representative case

`packages/bench/fixtures/long-noisy-openai.json` (deterministically generated by
`fixtures/gen-long.mjs`): 64 OpenAI-format messages, 12,667 estimated tokens. An agent is asked to
fix a flaky idempotency test under two constraints, then detours through an unrelated eslint
upgrade (an `npm install` log, 23 lint errors, seven patches), repeats the identical failing test
run three times, chats about a broken coffee machine, and finally fixes the bug. Budget: 6,000 tokens.

| arm | tokens after | saved | latency | cost | path fidelity | hallucinated paths | evidence retention |
|---|---|---|---|---|---|---|---|
| **jev-compactor** | **4,493** | **64.5%** | **366 ms** | **$0.0004** | **100%** | **0** | **100%** |
| truncate-oldest | 5,957 | 53.0% | 1 ms | $0 | 100% | 0 | 25% |
| summarize (Sonnet 5) | 486 | 96.2% | 6,141 ms | $0.0305 | 92.3% | 1 | 75% |

Reading it: truncation keeps the recent half and therefore loses the tickets, the freeze and the
original failure — three of the four things the user asks about in the final turn. Summarization
compresses hardest but drops one of the four facts, writes one reference that does not exist in
the transcript (`db/client.ts`, a shortening of `src/db/client.ts`), and costs 76× more and takes
17× longer than jev-compactor. jev-compactor drops the whole lint detour and the duplicate runs,
keeps the constraints (the first user message is pinned by goal path, and Jev rates it a keep), and
lands under budget with every fact intact.

## Short, dense fixtures — the conservative case

`packages/jev-compactor/fixtures/*.json`: the same 33–35-message story in four message formats,
about 5,500 tokens each, nearly every message on-topic. Budget: 4,000 tokens — a 27% cut.

| arm | saved (mean) | latency (mean) | cost (mean) | path fidelity (mean) | hallucinated paths (total) | evidence retention (mean) |
|---|---|---|---|---|---|---|
| **jev-compactor** | 23.8% | 295 ms | $0.0002 | **100%** | **0** | **100%** |
| truncate-oldest | 25.6% | 0 ms | $0 | 100% | 0 | 75% |
| summarize (Sonnet 5) | 84.5% | 8,769 ms | $0.0189 | 100% | 0 | 33.3% |

Per transcript:

| transcript | jev-compactor saved / retention | truncate saved / retention | summarize saved / retention |
|---|---|---|---|
| openai-tool-loop | 26.4% / 100% | 30.0% / 66.7% | 83.2% / 33.3% |
| anthropic-tool-loop | 17.5% / 100% | 29.3% / 66.7% | 82.0% / 33.3% |
| langchain | 26.4% / 100% | 30.1% / 66.7% | 86.5% / 33.3% |
| plain-chat | 25.0% / 100% | 12.9% / 100% | 86.3% / 33.3% |

Reading it: when almost everything is relevant, jev-compactor refuses to hit the budget rather than
drop evidence — the goal-path and code pins alone exceed 4,000 tokens on these fixtures, and the
report says so (`tokensAfter` above `maxTokens`, every drop attributed). Truncation hits the budget
and loses a third of the evidence. Summarization keeps every path real here but loses two thirds of
the evidence while costing about 90× more.

## What this does and does not show

- The transcripts are synthetic and short by real-session standards; they are in the repo so the
  numbers are reproducible, not because they are representative of your agent. Drop your own
  transcripts (Claude Code `.jsonl`, fast-jev-compaction JSON, or any messages JSON) into
  `packages/bench/local/` and re-run.
- Token counts are estimates (2.5 characters per token), applied identically to every arm; Jev's own
  tokenizer runs denser on JSON, which is why the compactor re-abridges on demand.
- **Jev's answers are not bit-stable.** Given the same answers the compactor is deterministic, but
  across identical requests Jev's P(keep) for a unit moved by up to 0.14
  (`packages/bench/scripts/determinism.mjs`, four runs on the long transcript: no decision changed,
  4,423 tokens after every time). A unit that sits near the 0.7 drop threshold can therefore flip
  between runs; the paired runs the harness records caught that twice in nine transcripts-runs. Raise
  `dropThreshold` if that matters more to you than compaction ratio.
- Summarization quality depends on the prompt and model; the prompt used is in
  `packages/bench/baselines/anthropic.mjs`, and it explicitly asks for exact paths and errors.

## Reproduce

```sh
pnpm install && pnpm --filter jev-compactor build
cd packages/bench
pnpm exec tsx src/run.ts ../jev-compactor/fixtures --goal "Fix the failing unit test in src/auth.ts" --max-tokens 4000 \
  --baseline baselines/truncate.mjs --baseline baselines/anthropic.mjs \
  --must-contain "expected null to deeply equal" --must-contain "CLOCK_SKEW_MS" --must-contain "export function signSession"
pnpm exec tsx src/run.ts fixtures/long-noisy-openai.json --max-tokens 6000 \
  --baseline baselines/truncate.mjs --baseline baselines/anthropic.mjs \
  --must-contain "OPS-2291" --must-contain "API-1187" --must-contain "duplicate idempotency key" --must-contain "migration freeze"
```

`TYPESAFE_API_KEY` is required; `ANTHROPIC_API_KEY` only for the summarization arm (omit that
`--baseline` to skip it).
